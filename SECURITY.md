# Security Policy

## Reporting a vulnerability

Do not report suspected vulnerabilities through public issues, pull requests, or GitHub Discussions.
Use the repository's private vulnerability reporting form instead:

<https://github.com/setu-ts/setu-ts/security/advisories/new>

Include the affected package and version, runtime, a minimal reproduction or proof of concept, the
impact you observed, and any suggested mitigation. Do not include production credentials or personal
data.

The form is also the confidential route for a Code of Conduct concern; begin that report with
`CODE OF CONDUCT:` and describe the concern without publishing it elsewhere.

## Supported versions

Security fixes are considered for the latest published Setu-TS release. When a report affects an
older release, maintainers may ask for confirmation against the current release before deciding
whether a backport is appropriate.

## Disclosure

Maintainers will use the private advisory thread to acknowledge a report, assess it, coordinate a
fix, and agree on disclosure timing with the reporter. Please give maintainers reasonable time to
address a validated issue before public disclosure.
